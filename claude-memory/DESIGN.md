## 1. 为什么做

一群朋友分散在美东、美中和国内，想一起玩你画我猜。用过几个网页版和微信小程序，总有地方不顺手：

- 有人猜对之后显示的内容不对胃口
- 词库没法自定义
- 画画工具不是太多就是太少
- 有人数上限

所以干脆自己做一个，规则按自己的习惯来，能改的东西都放进配置文件。

**成功的样子**：在群里发一个链接，大家用手机浏览器点开就能玩一整晚，中途没人因为卡顿、掉线或规则问题扫兴。

## 2. 目标

1. 手机浏览器优先（iPhone Safari、安卓 Chrome），电脑浏览器也能玩。不做 App。
2. 美东、美中、国内三地的人能同时顺畅地玩。
3. 规则、时长、人数、词库、颜色这些都写在配置文件里，不写死在代码里。
4. 代码模块化，以后加联想模式之类的新玩法，不用改核心代码。

## 3. 这一版不做的事

- 联想模式等新玩法（只把扩展的位置留好，见第 8 节）
- 在网页上传词库（词库由房主自己往文件夹里放）
- 账号注册、历史战绩、跨局排行榜
- 观战席（进房的人都是玩家）
- 撤销上一笔、油漆桶填充等额外的画画工具
- "猜得很接近"之类的提示
- 音效 〔我定〕
- 房间密码 〔我定：只在朋友之间传链接，不设门槛〕

## 4. 绝对不能出现的情况

- 国内的朋友打不开或者非常卡。原因可能是用了被墙的服务（Google 字体、部分 CDN、Firebase 等）。
- iPhone 切到微信再切回来就掉线，或者分数丢了。
- 想改个时长或人数却得改代码。
- 新玩法的逻辑和核心代码纠缠在一起，加一个模式要动很多文件。
- 画画工具做得臃肿。

## 5. 约束

- **Python 环境**：用项目自己的环境（`environment.yml` 建的 conda 环境 `nhwc`，或者虚拟环境），绝不装进系统 Python。（开发时用的是作者电脑上的 Python 3.13.1 环境。）
- **两种部署方式都要能跑**：在你的 Windows 电脑上跑，和在 Linux VPS 上跑，必须完全一样。部署方式还没定（见第 9 节）。
- **所有资源都放在本服务器上**：不加载任何外部 CDN 或字体，字体用系统自带的。
- **模块化**：每个文件只负责一件事，避免巨型文件（CLAUDE.md 要求）。
- **界面语言**：只做中文。〔我定〕

## 6. 玩法

### 6.1 进房

- 首页可以"创建房间"，系统生成一个短房间码，链接形如 `/r/ABCD`。〔我定：支持多个房间并存，成本很低，也方便测试〕
- 拿到链接的人点开、输个昵称就能进，不用注册。
- 创建房间的人就是**房主**，房主本人也参与游戏。
- 房主在等待界面调这一局的设置（见 6.8），然后点"开始"。开始至少需要 `min_players` 人。
- 房主的权限：开始游戏、踢人、跳过当前这个词。被踢的人这个房间进不来了。〔我定〕
- 房间满员（`max_players`）时，新来的人会看到"房间已满"。昵称重名时自动加个数字后缀。〔我定〕
- 房主掉线超过 `host_transfer_seconds` 秒，房主身份交给在线玩家里最早进房的那个人。〔我定〕

### 6.2 一局的流程

```
等待界面 ──房主点开始──▶ 一圈：每人轮流当一次画手（按进房顺序）
                          │
                          ▼
            ┌─ 选词：画手从随机抽出的 N 个词里选一个
            │       （超过 choose_seconds 秒没选，就随机替画手选）
            │
            ├─ 作画/猜词：倒计时 draw_seconds 秒
            │       遇到下面任意一种情况就结束：
            │       · 时间到
            │       · 除画手外所有在线玩家都猜对了
            │       · 房主点了跳过
            │       · 画手掉线超过 drawer_offline_skip_seconds 秒
            │
            └─ 公布：显示答案、谁猜对了、每人这轮得了多少分
                    停留 reveal_seconds 秒，然后轮到下一个画手
                          │
                 打满 rounds 圈后
                          ▼
                 最终排名 ──▶ 回到等待界面（可以直接再开一局）
```

- 同一局里同一个词不会重复出现。〔我定〕
- 中途进房的人排到当前这一圈的末尾，等轮到时再画；进房时如果正在作画，可以马上参与猜词。〔我定〕
- 词库里的词用完了，就允许重复出现。〔我定〕
- 如果在线人数少于 `min_players`，这局直接结束，进入最终排名。〔我定〕

### 6.3 时间控制

- **缩短倒计时**：可以配置成：第一个人猜对后，剩余时间缩短到 `shorten_to_seconds` 秒；如果本来剩下的时间就更少，则不变。开关和秒数都可以配置。
- **画手手动加时**：作画期间，画手可以点"+10秒"按钮给自己加时间。每次加多少秒（`extend_seconds`，默认 10）、每轮最多加几次（`max_extends_per_turn`，默认 3）都可以配置。〔次数上限是我定的〕
  - 加时不扣分；缩短倒计时触发之后照样可以加。〔我定〕

### 6.4 提示

- **字数提示（可开关）**：开启时，猜词的人能看到 `_ _ _`，下划线的数量就是字数。词里的空格不算字数，显示成间隔。〔我定〕
- **画手主动揭字**：作画期间，画手可以点自己那个词里的某一个字，把它亮给所有人看，比如长颈鹿变成 `_ 颈 _`。可以揭多个字，但最多揭到 `字数 - 1` 个。
  - 揭了字就等于暴露了字数，所以即使字数提示是关着的，揭字之后也会显示完整的下划线格式。〔我定〕
- **揭字的代价**：在计分上体现，见 6.6。

### 6.5 聊天栏和猜词

- 猜词和聊天共用一个输入框。
- **判定规则**：先做规范化处理（去掉空格和标点、全角转半角、英文不区分大小写）；如果规范化后的消息**包含**答案，就算猜对。〔我定：这样像"是不是长颈鹿"这种说法也算对，而且不会把答案漏给别人。代价是答案只有一个字时可能误判，比如答案是"猫"、有人说"熊猫"，但一个字的词本来就很少。〕
- **猜对的显示**：别人看到的是 `小王：***`，星号个数等于答案字数，并且加高亮表示"猜对了"。猜对的人自己能看到答案。
- **猜错的显示**：原文照常显示给所有人。
- **知道答案的人单独一个频道**：作画期间，画手和已经猜对的人发的消息，只有画手和已猜对的人能看到，免得不小心剧透。〔我定：画手也归这个频道〕
- 等待界面、公布阶段、最终排名阶段，聊天对所有人公开。

### 6.6 计分（具体参数全部可配置）〔整套公式都是我定〕

- **猜对的人**：`分数 = max(G_min, round(G_max × 剩余时间 / draw_seconds)) × 揭字系数`
  - "剩余时间"是猜对那一刻倒计时上的数，所以触发缩短倒计时之后再猜对，得分自然就低了。
  - 画手加时后，剩余时间可能超过 `draw_seconds`，这时按 G_max 计分。
- **画手**：每有一个人猜对，画手得 `D × 当时的揭字系数`。没人猜对就是 0 分。
- **揭字系数**：`reveal_factor ^ 已揭字数`。揭字之前就已经猜对的人不受影响。也就是说，揭字会让画手和之后才猜对的人一起少拿分。
- 默认值：G_max = 100，G_min = 20，D = 25，reveal_factor = 0.75。
- 计分逻辑做成独立模块，换一个新模式就可以整套替换。

### 6.7 画画

- **工具**：画笔、橡皮、一键清空（清空前要确认一下，防止手机上误触）〔确认这一步是我定的〕。
- **粗细**：画笔和橡皮的粗细，都从几档预设里选，比如细、中、粗、特粗；具体有几档、每档多粗都在配置里。〔我定：手机上点预设比拖滑条好用〕
- **颜色**：默认 7 种（黑、红、橙、黄、绿、蓝、棕），颜色列表在配置里。画布底色是白色。
- 只有画手能画。笔画实时同步给其他人，延迟到几百毫秒都可以接受（这个游戏本来就不怎么拼手速）。
- 画布用统一的逻辑坐标和固定比例，所以手机和电脑看到的是同一张画。
- 中途进房或重连的人，进来就能看到当前这幅画已经画了的全部内容。
- 在 iPhone 上画画时，页面不能跟着滚动或缩放。

### 6.8 配置

**服务器配置文件** `config.toml`〔我定用 TOML 格式：可以写注释，而且 Python 3.13 自带读取它的库〕：

| 分组 | 内容 |
|---|---|
| server | 监听地址、端口 |
| room | `max_players`、`min_players`、`host_transfer_seconds`、`drawer_offline_skip_seconds` |
| game（每局默认值） | `rounds`、`draw_seconds`、`choose_seconds`、`word_choices`、`show_length_hint`、`shorten_after_first_correct`、`shorten_to_seconds`、`extend_seconds`、`max_extends_per_turn`、`reveal_seconds` |
| scoring | `G_max`、`G_min`、`D`、`reveal_factor` |
| drawing | 颜色列表、画笔粗细档位、橡皮粗细档位 |
| words | 词库文件夹路径 |

**房主在等待界面可以改的设置**（会覆盖配置文件里的默认值，只对这个房间生效）：用哪几个词库、圈数、作画时长、选词数量、字数提示开关、缩短倒计时的开关和秒数，以后还有模式选择。其余设置只能改配置文件，改完重启服务器生效。（你说过，哪些设置放界面、哪些放配置文件都无所谓，只要不用改代码就行。）

**词库**：

- 词库文件夹里每个 `.txt` 文件是一个词库，词库名就是文件名。
- 文件用 UTF-8 编码，一行一个词。空行和以 `#` 开头的行会被忽略，重复的词会被去掉。
- 每次打开等待界面都会重新扫描文件夹，新放进去的词库不用重启服务器就能用。〔我定〕
- 先附一个默认词库，让游戏开箱就能玩。

### 6.9 断线重连（重点）

- 每个玩家第一次进房时，会在浏览器里存一个随机身份令牌。重连时凭这个令牌回到原来的位置，分数、轮次都保留。
- 掉线的人在玩家列表里显示成灰色，不会被移出这一局。轮到掉线的人画时直接跳过。〔我定〕
- 页面从后台切回来时，自动检测连接是否断开并重连，重连后拿到当前完整的状态：阶段、倒计时、画面、聊天、分数。
- 浏览器存储如果不可用（比如无痕模式），游戏照样能玩，只是失去重连能力。

## 7. 架构

### 7.1 整体

- **后端**：一个 Python 异步服务进程，同时提供网页文件和 WebSocket 连接，只占用一个端口。〔我定；推荐用 FastAPI/Starlette + uvicorn，最终用哪个库交给开发阶段决定〕
- **前端**：纯 HTML/CSS/JS，用浏览器原生支持的 ES modules，不需要打包构建，也不依赖外部 CDN。
- **状态全部放在内存里**，不用数据库。服务器重启后房间就没了，朋友之间玩可以接受。〔我定〕
- **核心逻辑不依赖网络**：游戏规则这部分（阶段切换、判定、计分）是纯逻辑，不碰网络，可以直接用 pytest 测试。时间来源也要能注入，这样测试时不用真的等倒计时。

### 7.2 模块划分（概念上的边界，具体文件怎么拆交给开发阶段）

**后端**

- **配置加载**：读取 `config.toml`，和房主在等待界面的设置合并，并做校验。
- **词库**：扫描文件夹、解析 txt、抽词、去重。
- **房间和玩家**：创建房间、进出房间、房主身份、身份令牌、在线状态。
- **连接层**：WebSocket 收发和消息分发。这一层不懂游戏规则。
- **计时器**：倒计时、缩短倒计时、超时回调。
- **画布同步**：笔画缓存、广播、重连时补发全部内容。
- **模式（Mode）**：一局游戏的流程、判定规则、各人能看到什么、计分。经典模式是第一个实现。
- **计分策略**：由模式选用，可以单独替换。

**前端**

- 连接与重连
- 画布（绘制、接收别人的笔画、坐标换算）
- 工具栏
- 聊天栏
- 玩家列表和分数
- 倒计时
- 提示区（下划线和揭字）
- 各阶段的界面（等待、选词、作画、公布、最终排名）
- 和具体模式有关的界面部件

## 8. 留给后续扩展：新模式怎么接进来

- 核心部分（房间、连接、玩家、画布同步、计时器、聊天传输）**不了解任何具体规则**。
- 一个模式要定义这几件事：有哪些阶段、阶段怎么切换、玩家的消息怎么判定、每个人分别看到什么、怎么计分、有哪些可配置项。
- 前端对应每个模式有一组界面部件，按模式名注册。
- **加一个新模式 = 新增一个后端模式模块 + 一组前端部件 + 一段配置**，核心代码不用改。
- 设计接口时要拿联想模式这类玩法来检验，看接口是否足够灵活：比如多人接力画、每一轮的题目来自上一轮、猜词结果会影响下一步。联想模式的具体规则以后再定。

## 9. 部署（现在不定）

- 第一步：在你自己的电脑上跑起来，同一个局域网里的手机先测。
- 第二步：给外地朋友访问。可以在路由器上做端口转发，或者用内网穿透工具，到时候再选。
- 如果国内朋友卡：换成洛杉矶（选对国内有优化线路的）或日本的小 VPS，每月几美元，到美东、美中、国内的延迟都比较平均。服务器在境外，不需要备案。
- 服务要能放在反向代理后面（比如以后加 HTTPS），WebSocket 地址根据当前页面的地址自动推算，不写死。

## 10. 风险

| 风险 | 应对 |
|---|---|
| 微信内置浏览器可能拦截陌生链接或 IP 地址链接 | 让朋友点右上角"在浏览器打开"；以后有需要再配域名 |
| iPhone Safari 切到后台会断开连接 | 6.9 节的令牌重连 + 回到前台时自动检测 |
| 跨太平洋的线路晚上丢包严重 | 先测；不行就搬到对国内有优化线路的 VPS |
| 手机上画画时页面跟着滚动或缩放 | 画布区域禁止触摸手势的默认行为，用真机测试 |
